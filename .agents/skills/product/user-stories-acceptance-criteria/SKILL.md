# User Stories & Acceptance Criteria

## Formato
Como [actor], quiero [capacidad], para [beneficio]. Añadir reglas de negocio y contexto cuando sea necesario.

## Procedimiento
1. Dividir épicas en historias verticales pequeñas que entreguen valor.
2. Añadir ID estable, prioridad, dependencias y requisito de origen.
3. Escribir criterios Given/When/Then observables.
4. Cubrir éxito, errores, límites, permisos, estados vacíos y concurrencia relevante.
5. Definir datos de prueba, precondiciones y resultado esperado.
6. Añadir requisitos no funcionales medibles: rendimiento, accesibilidad, privacidad y seguridad.
7. Revisar INVEST: independiente, negociable, valiosa, estimable, pequeña y comprobable.

## Definition of Ready
Problema claro, actor identificado, alcance acotado, dependencias conocidas y criterios comprobables.

## Definition of Done
Criterios satisfechos, pruebas ejecutadas, revisión de seguridad/accesibilidad cuando aplique, documentación y evidencia.

## Antipatrones
No usar "rápido", "fácil" o "seguro" sin escenarios o umbrales. No prescribir implementación salvo restricción necesaria.
